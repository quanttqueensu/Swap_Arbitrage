# P40 naive complete-strategy backtest verification

## Objective, scope, and versions

P40 adds a standard-library causal replay engine under `backtesting/`. It calls
a supplied pure shared-strategy function whose outputs are the existing Phase 4
`SignalDecision`, `RiskDecision`, and `OrderIntent` records. It does not copy
signal, sizing, risk, or portfolio equations and does not import the legacy
99-column backtest output.

- Strategy specification: `p10.strategy-equations.v1`.
- Backtest configuration: `p40.naive.v1`.
- Maturity label: `complete_2y_5y`.
- Evidence class: `synthetic_mechanics_only`.
- Window policy: `start_flat`.
- Runtime: Python 3.12.13.

The user explicitly approved MG5 on 2026-08-09. The P35 blockers remain
recorded: this work does not claim that canonical maturity-matched swap rates,
active executable contracts, liquidity, or roll data now exist.

## Fixed naive assumptions

| Assumption | Value |
| --- | ---: |
| Bid/ask half-spread | 0.01 points per filled contract |
| Commission/exchange | 1 USD per filled contract |
| Slippage | 0.005 points per filled contract, capped by the intent |
| Financing not already in funding | 0.10 USD per held contract per calendar day |
| Roll close/open | 1 USD per filled roll contract |

The manifest writes every assumption by name. These values are synthetic
mechanics inputs, not observed execution evidence or a calibration claim.

## Causal event and accounting contract

For each ordered replay event, the engine:

1. marks positions held from the prior event using only same-contract prices;
2. charges elapsed-day financing on those prior positions;
3. fills only intents queued by an earlier event and currently eligible;
4. applies partial or rejected fill capacity and updates positions;
5. invokes the shared strategy with current positions and working orders;
6. queues new intents only after fill processing; and
7. records daily accounting and end-of-event positions.

Thus a decision cannot fill on its own event. Missing held-position marks are
counted rather than silently treated as complete data. Date windows begin flat
and say so in the manifest. Appending a future event leaves every earlier
daily, decision, and fill record unchanged.

## Hand-reconciled five-day golden run

The golden entry buys 2 YIT and sells 1 ZT. The next day's mark moves YIT from
100.00 to 100.10 and ZT from 100.00 to 99.98. The exit then sells 2 YIT and
buys 1 ZT.

| Date | Gross P&L | Transaction cost | Financing | Net P&L | Equity | Drawdown | End positions |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 2026-01-01 | 0 | 0 | 0 | 0 | 1,000,000.00 | 0 | flat |
| 2026-01-02 | 0 | 0 | 0 | 0 | 1,000,000.00 | 0 | flat; entry queued |
| 2026-01-03 | 0 | 48.00 | 0 | -48.00 | 999,952.00 | 48.00 | YIT +2, ZT -1 |
| 2026-01-04 | 220.00 | 0 | 0.30 | 219.70 | 1,000,171.70 | 0 | YIT +2, ZT -1; exit queued |
| 2026-01-05 | 0 | 48.00 | 0.30 | -48.30 | 1,000,123.40 | 48.30 | flat |

Fill reconciliation:

| Date | Instrument | Side | Quantity | Mid | Execution | Cost |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 2026-01-03 | YITH27 | BUY | 2 | 100.000 | 100.015 | 32.00 |
| 2026-01-03 | ZTH27 | SELL | 1 | 100.000 | 99.985 | 16.00 |
| 2026-01-05 | YITH27 | SELL | 2 | 100.100 | 100.085 | 32.00 |
| 2026-01-05 | ZTH27 | BUY | 1 | 99.980 | 99.995 | 16.00 |

The held-position mark is
`2 * 1000 * (100.10 - 100.00) + -1 * 1000 * (99.98 - 100.00) = 220 USD`.
Each three-contract holding day costs `3 * 0.10 = 0.30 USD` financing. Every
daily row satisfies `net = gross - transaction cost - financing` exactly.

Separate tests reconcile a direct reversal as six filled contracts and charge
96 USD, and a roll close/open as four ordinary fill costs plus four roll
charges, totaling 68 USD.

## Outputs

`write_results` validates exact headers and unique keys, writes UTF-8 CSV to a
temporary sibling, then replaces each destination. Repeated writes of the same
result are byte-identical. The manifest records `p40.backtest.v1`, coverage,
per-report row counts, an input SHA-256, and a SHA-256 for every non-manifest
artifact. Every run directory contains exactly:

- `manifest.csv`
- `daily.csv`
- `decisions.csv`
- `orders.csv`
- `fills.csv`
- `trades.csv`
- `positions.csv`
- `summary.csv`

`daily.csv` uses the approved ten-column schema. Summary diagnostics include
maximum gross DV01, turnover, transaction and financing costs, missing-input
count, risk-blocked days, equity, and drawdown.

sub-agent was spawned. A scoped re-check found that summary and manifest row
counts were still omitted; a final failing report assertion drove those two
fields, and the same reviewer returned `PASS` after the fix.
