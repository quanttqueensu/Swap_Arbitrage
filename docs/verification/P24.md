## Review findings and resolution

Independent review initially found two publication defects. A critical finding
showed that caller-constructed run-manifest metadata could claim false
provenance; the generic finalization helper was removed, and P24 now creates the
manifest only from recorded execution evidence after publication. An important
TOCTOU finding covered destination leaf and parent replacement; publication was
hardened with parent locks/descriptor-relative operations, late-leaf tests, and
rollback. Follow-up POSIX descriptor review and Windows parent-lock review were
clean. A real-data dry run then exposed blank optional rate observations; the
implementation now omits only exact-empty consumed series while retaining
fail-closed validation for malformed, nonfinite, and nonpositive values. Its
focused independent review returned `CLEAN` with no findings. No P24 review
finding remains unresolved. The final whole-package review independently
revalidated both manifests, all 31 published files against both retained
stages, both reports, the 26,146-row total, timestamps, configuration and code
identity, source immutability, evidence completeness, and commit exclusions; it
returned `CLEAN` before controller review.

Controller review then found a critical post-syscall journal gap and an
important cleanup-control gap. Successful replace/link syscalls could be absent
from the journal when the following POSIX directory verification failed; the
caller now journals synchronously inside each helper before verification.
Cleanup now attempts every sibling and every unique guard, annotates an active
rollback exception with aggregated cleanup errors, and explicitly reports a
committed transaction if only cleanup was incomplete. The four regressions were
observed RED, then GREEN; independent scoped review returned `CLEAN`. A final
review found one more claim-allocation boundary: the claim path was recorded
only after its fallible unlink. It is now recorded immediately after successful
creation. Its exact-boundary regression was RED with one leaked claim and GREEN
after the one-line fix; publication tests passed 13/13 and independent review
again returned `CLEAN`. The corrected real publication used the resulting exact
commit `8f2aab33b142e80ea8491e8b571c81a65fc3fd18`.

The post-commit byte audit then found that Git's repository-wide automatic text
normalization altered only the committed `p24_inputs.csv` blob, which would
break the exact digest recorded above on a platform with different checkout
settings. The file's published bytes were still intact. A path-specific
`data/manifests/p24_inputs.csv -text` rule now preserves this checksum-bearing
manifest byte-for-byte; the re-indexed blob and published file both hash to
`b7c4674d0a8019c315fe541a0fb3b9f64a3acef9ceea9c722baff15c9ebb471f`.
Focused review first rejected the byte-preservation change because bare
`-text` made `git diff --check` treat the preserved CR characters as trailing
whitespace. The final path rule adds `whitespace=cr-at-eol`; exact-byte and
cached/working diff checks then passed and the reviewer returned `CLEAN`.
