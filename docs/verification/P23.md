# P23 verification evidence — IBKR paper recorder

## Objective and scope

P23 adds a paper-only IBKR event recorder and an atomic, schema-driven CSV
event store. The recorder validates a supplied paper session, requests quote
objects through an injected broker, and records quotes, orders, fills, and
position snapshots. It does not create a broker connection, submit an order,
or cancel an order. This record covers the final whole-P23 implementation and
review state handed to P24.

## Broker-safety, privacy, and normalization evidence

The test module installs guards for `socket.socket.connect`, `connect_ex`,
`sendto`, `socket.create_connection`, and `socket.getaddrinfo` before importing
the P23 modules, and keeps them active for the module lifetime. Therefore any
socket/DNS attempt in the 37 focused recorder/store tests fails immediately.
The recorder uses the injected `FakeIB`; unsafe-session tests also assert zero
`isConnected`, `managedAccounts`, and market-data-request calls. Combined with
the zero production scan counts and exact six-method surface above, the
observed P23 test path has zero network, order-submit, and cancel invocations.

Session validation requires `type(client_id) is int` and the exact value `30`,
so booleans and `30.0` fail. The configured account must match `DU` followed by
one or more digits. The recorder rejects any row containing its configured
account, while the store rejects numeric and symbolic DU/U account forms; all
privacy errors are generic and do not echo the value.

IBKR execution sides `BOT` and `SLD` normalize to canonical schema values
`BUY` and `SELL` before signed fill quantity is derived. Positive IDs are also
canonicalized before persistence.

Broker request/quote property reads, ticker scalar extraction, and broker call
failures are handled within an untrusted boundary. The passing quote test
requires generic `PaperSafetyError` text, no sensitive marker in formatted
tracebacks, and detached `__cause__` and `__context__`.

The same detached boundary parses every broker-derived numeric scalar. The
14-field regression covers four quote fields; order quantity and order ID;
execution shares and price; commission; and position quantity, average cost,
market price, unrealized P&L, and realized P&L. Each hostile scalar contains
credential, endpoint, and client-ID text. All 14 cases pass only when the error
is generic, those markers are absent, and cause/context are detached. Valid
numeric values still receive field-specific finite, sign, positive, or
nonnegative semantic validation outside the untrusted conversion boundary.

### Whole-P23 review rounds

The whole-P23 review used separate broker-safety and data/schema lenses.

* Round 1 found incomplete IBKR `BOT`/`SLD` adaptation, permissive account and
  client configuration values, standalone-store symbolic-account gaps,
  configured-account row leakage, request/quote and broker-object exception
  leakage, and missing module-lifetime network/public-surface proof. Commit
  `867bfb4` closed those boundaries and added the related regressions.
* Round 2 found that all 14 broker numeric fields still parsed detached strings
  outside the untrusted boundary, permitting conversion errors to retain or
  echo broker-controlled text. Commit `f58c737` moved numeric parsing into the
  detached boundary and added the exhaustive 14-field regression.

After round 2, the final broker-safety review verdict was clean and the final
data/schema review verdict was clean. No unresolved P23 review finding remains
in the supplied review record.
