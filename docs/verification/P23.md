# P23 verification evidence — IBKR paper recorder

## Objective and scope

P23 adds a paper-only IBKR event recorder and its atomic CSV event store.  The
scope is restricted to recording paper quotes, orders, fills, and position
snapshots; it does not submit orders, cancel orders, or establish broker
connections.  This record covers the implementation sequence from the P23
baseline through the final P23 implementation commit, and is the hand-off
evidence for P24.

## Fake-broker and redaction evidence

The P23 recorder tests use `FakeIB`; its only broker-facing recording is the
`market_data_requests` list, and it has counters for `isConnected` and
`managedAccounts`.  The passing unsafe-configuration and unsafe-record-quote
tests assert `is_connected_calls == 0`, `managed_account_calls == 0`, and
`market_data_requests == []` before validation can access the fake broker.
The production-module scan above found zero occurrences of the three
order/cancellation methods (`placeOrder`, `reqGlobalCancel`, `cancelOrder`).
Together with the injected fake broker in the passing recorder tests, this is
the P23 evidence of zero network invocation, zero order submission, and zero
cancellation invocation by the recorder test path.

The full 172-test run includes the redaction tests
`test_rejects_sensitive_values_without_echoing_them`,
`test_broker_failures_and_malicious_aliases_never_leak_to_traceback`,
`test_rejects_broker_property_failures_without_secret_tracebacks`, and
`test_rejects_broker_raised_safety_errors_without_secret_tracebacks`.  They
exercise DU account identifiers, credentials, endpoint text, and client IDs.
For broker failures and hostile broker properties, the tests require generic
`PaperSafetyError` output, assert the sensitive strings are absent from the
formatted traceback, and assert both `__cause__` and `__context__` are `None`.
The duplicate-key and sensitive-store tests also assert that sensitive input
values are not echoed in raised errors.

## Review findings and resolutions

The P23 progress ledger records the following review-driven corrections:

| Area | Finding | Resolution |
| --- | --- | --- |
| Store round 1 | Ordering, dot-segment IDs, sensitive values, and coverage needed hardening. | Parsed ordering, dot-segment rejection, sensitive-value checks, and coverage added (`9b18db3`). |
| Store round 2 | IP hosts and duplicate-key redaction were incomplete. | Rejected IP/host values and made duplicate-key errors generic (`22989a4`). |
| Store round 3 | Host detection was too broad. | Scoped ambiguous-host detection by schema field (`c31a6ad`). |
| Store round 4 | Exact endpoints could pass in other string fields. | Rejected exact endpoints across string fields (`a4ce155`). |
| Store round 5 | Single-label host-plus-port values could pass. | Rejected numeric-port single-label endpoints (`d9aedc4`). |
| Session round 1 | Client ID was not exact and broker failures could disclose alias/configuration. | Required client ID 30 and raised detached generic session errors (`0b3b244`). |
| Session round 2 | A hidden broker exception remained in `__context__`. | Raised after the handler so cause and context are both absent (`1fdcd12`). |
| Event round 1 | Hostile broker properties could escape; acknowledged order IDs could be replaced. | Isolated broker-object normalization and limited order-ID reconciliation (`6b6c222`). |
| Event round 2 | A hostile object could forge `PaperSafetyError` and leak its message. | Treated every broker-traversal exception as untrusted and detached it (`e489762`). |
| Event round 3 | Digit-text contract IDs were not canonical. | Canonicalized positive contract IDs before persistence (`a242782`). |

The progress ledger marks each final review round clean: store round 5,
session round 2, and event round 3.
